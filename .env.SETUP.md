# Environment Configuration Guide

This project uses a **single comprehensive `.env.example`** file as the source of truth for all configuration variables.

## Quick Start

### Backend Setup

1. **Copy the template:**
   ```bash
   cp .env.example .env
   ```

2. **Edit `.env` with your actual values:**
   - Database: Your MongoDB connection URI
   - JWT secrets
   - CORS origins
   - Email credentials
   - AWS S3 credentials (optional)

3. **For development:** The `.env.development` file has sensible defaults that override `.env` when running locally

### Frontend Setup

1. **Copy the template:**
   ```bash
   cp .env.example .env.local      # for local development
   cp .env.example .env.production # for production builds
   ```

2. **Edit `.env.local` for development:**
   - Leave `VITE_API_URL` empty (uses Vite proxy to localhost:4000)
   - Or set to `http://localhost:4000` if Vite proxy isn't configured

3. **Edit `.env.production` for production builds:**
   - Set `VITE_API_URL` to your actual backend domain
   - Example: `https://api.kangaru-girls.ac.ke`

## File Structure

### `.env.example`
The master template with all possible variables and documentation. Never edit this for actual secrets.

### `.env` (git-ignored)
Your actual secrets and configuration. Create from `.env.example`. Never commit!

### `.env.development` (optional, git-ignored)
Development-specific overrides. Vite/Node automatically loads this as environment-specific defaults.

### `.env.production` (optional, git-ignored)
Production-specific configuration for production builds (frontend) or production deployment (backend).

## Important Notes

### Environment Variables

- **Backend:** All env variables are read at NODE startup (dotenv.config())
- **Frontend:** Vite only includes variables prefixed with `VITE_` in the build, and they're embedded at BUILD TIME
  
  This means to change `VITE_API_URL` in production, you must **rebuild** the frontend with the new value.

### CORS Configuration

The backend accepts CORS requests from origins listed in `CORS_ORIGINS` env variable.

**⚠️ SECURITY WARNING:** If `CORS_ORIGINS` is empty or not set, the backend accepts requests from ANY origin!

Always set explicit origins in production:
```
CORS_ORIGINS=https://kangaru-girls.ac.ke,https://api.kangaru-girls.ac.ke
```

### Database

Backend checks for MongoDB URI in this order:
1. `MONGO_URI` ← use this one
2. `MONGO_URL`
3. `MONGODB_URI`
4. `DATABASE_URL`

Pick ONE and use it consistently.

## Development Workflow

```bash
# Backend
cd kscbackend
cp .env.example .env
# Edit .env with your values
npm run dev

# Frontend
cd kscfrontend
cp .env.example .env.local
# Leave VITE_API_URL empty (uses Vite proxy)
npm run dev
```

## Production Deployment

### Backend (Render/Railway/Heroku)
1. Copy all variables from `.env.example` to your platform's environment variables
2. Set `NODE_ENV=production`
3. Set secure `JWT_SECRET`, `ID_CARD_SECRET`, `ADMIN_PASSWORD_HASH`
4. Set proper `CORS_ORIGINS` (don't leave empty!)
5. Set `PUBLIC_ORIGIN` to your API domain
6. Configure email (SMTP or SendGrid)

### Frontend (Vercel/Netlify/Render)
1. Set `VITE_API_URL` to your backend domain
2. Build with: `npm run build`
3. Deploy the `dist/` folder
4. If you need to change API URL later, rebuild and redeploy
